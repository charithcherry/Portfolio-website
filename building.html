PROJECT 01 private repo · in progress

NeuroStack

A brain-inspired memory architecture for AI agents — because tools without memory aren't intelligence, they're just very fast tools.

"The most novel part of any agent architecture isn't the model. It's the memory."

// THE PROBLEM

An AI with no memory is a world-class expert who forgets you every morning.

Most agents today reinitialize their context on every API call. Your profile, your preferences, what you worked on last week — gone. Even thoughtful systems like OpenClaw store memory as flat Markdown — a brilliant filing cabinet, but not a brain.

# Today's agent memory memory: List[Markdown] = read_files("~/agent/memory/") context = stuff_into_prompt(memory[:N]) model.respond(context) # Same after 1 day. Same after 6 months. # No salience. No decay. No learning. # Trivial note == career decision.

// THE INSIGHT

The brain didn't evolve RAM. It evolved memory tiers.

Three layers, mapped to anatomy. NeuroStack implements all three.

tier 01

Hot Memory

prefrontal cortex

Who you are — always on, zero retrieval cost. Name, current role, active project. Lives in every prompt.

capacity: ~600–1500 chars · latency: 0ms
tier 02

Episodic Memory

hippocampus

What happened — timestamped events that decay over time. Retrieval strengthens the trace; cold memories fade.

decay: Ebbinghaus · strengthen: ACT-R
tier 03

Semantic Memory

neocortex

Facts distilled from experience — "Charith works in ML" not "on March 1st we discussed his job." Slow to form, lasts forever.

storage: knowledge graph · triples

// THE MATH

Retrieval strengthens memory.

ACT-R's base-level activation IS the Ebbinghaus forgetting curve, mathematically. Each access adds a fresh term — strong memories stay strong, unused ones fade.

Bi = ln ( Σ tj −0.5 )
Bi = activation of memory i
tj = time since jth access
−0.5 = decay rate (empirical)

Ebbinghaus gave us the forgetting curve in 1885. Anderson formalized it in 1998. We're applying it to context windows in 2026.

// THE LIFECYCLE

Memory is a lifecycle, not a lookup.

Most systems: store → retrieve → done. NeuroStack runs five stages.

Intake

salience-gated ingestion

Not everything is worth remembering. salience = 0.5 × surprise + 0.5 × LLM_importance decides what gets written, what gets discarded.

Active

always-on hot memory

High-salience, recently-accessed memories stay in context. Zero retrieval latency. Functions like working memory.

Decay

Ebbinghaus, 1885

Things you don't use fade. Not deleted — deprioritized. The forgetting curve is a feature, not a bug.

Consolidation

"sleep replay" · background process

A nightly job scans episodes > 24h old with high salience and extracts (entity, relation, entity) triples into the semantic store. Hippocampus → neocortex, in code.

Re-promotion

cold → hot, automatic

Asked about transformer attention three times this week? NeuroStack notices and bubbles it back into hot context. The agent learns what matters to you.

PROJECT 02 in development

Brain Component

A model-agnostic agent runtime built on NeuroStack — so I never have to depend on OpenAI, Anthropic, or anyone's API to keep working.

// WHY

Local-first. Provider-independent. Works offline.

  • No vendor lock-in. Swap Ollama → llama.cpp → Claude → GPT-4 with one config flag.
  • Privacy by default. Your conversations, memories, and tool calls never leave your machine unless you opt in.
  • Cost-bounded. Use a 7B local model for cheap iteration, route only the hard calls to a frontier model.
  • Resilient. If a provider rate-limits you or sunsets a model, you keep working.
# Brain Component architecture class Brain: memory: NeuroStack # 3-tier brain memory model: ModelRouter # local OR cloud tools: ToolRegistry # MCP-compatible agents: AgentNetwork # planner + workers router = ModelRouter( local = Ollama("llama3.2:8b"), cloud = Anthropic("claude-opus-4-7"), policy = "local-first", # cost-aware ) brain = Brain(memory=NeuroStack(), model=router) brain.run() # offline-capable

PROJECT 03 research · drafted

Adaptive Motion Intelligence

The missing layer between pose landmarks and movement understanding. A platform that generates the right movement analyzer for the right task, on demand.

// FROM POSE SNAPSHOTS TO ACTION SIGNATURES

Every action has a pattern over time. A movement isn't a set of frames — it's a repeatable signature that can be captured, scored, and compared.

// THE STATUS QUO

Pose detection is a wall.

  • × Most systems stop at skeleton detection.
  • × Apps are hardcoded for a few movements.
  • × New movements require manual logic.
  • × Motion products are rigid and slow to scale.

// THE GAP

Task-specific movement understanding.

Pose landmarks tell you where the joints are. They don't tell you whether the squat was deep enough, whether the elbow flared on the curl, or whether the rehab patient is making progress.

NOVEL PART · 01

The analyzer is generated, not just prewritten.

A user describes the movement they want tracked. An agent network generates the analyzer. A sandbox validates it. The runtime stays fast and deterministic.
